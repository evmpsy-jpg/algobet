# Инструкция для админов Algobet

Эта инструкция описывает ежедневную работу с Telegram-ботом и web-админкой. Оплата в проекте остается ручной: пользователь создает заявку, получает реквизиты и контакт, админ проверяет оплату и вручную выдает доступ.

## Доступ в web-админку

Адрес рабочей админки на VPS:

```text
http://217.114.5.208:48291/
```

При входе браузер попросит логин и пароль. Используйте свою пару из `WEB_ADMIN_USERS`.

Важные правила:

- не передавайте логин и пароль пользователям;
- не используйте пароль от админки в других сервисах;
- после спорных изменений проверяйте раздел `Журнал`;
- админка работает по HTTP, поэтому не открывайте ее в публичных сетях без необходимости.

## Ежедневная проверка

1. Откройте `Мониторинг`.
2. Сначала посмотрите блок `Состояние системы`.
3. Статус `OK` означает, что действие не требуется.
4. Статус `Внимание` означает рабочую задачу: новые заявки, старый backup или отсутствие загрузок.
5. Статус `Проблема` требует быстрой проверки: ошибки доставки, просроченные сигналы, ошибка импорта или невалидный backup.
6. Если есть ошибки доставки, откройте `Доставки` с фильтром `Ошибка`.
7. Если есть открытые заявки, перейдите в `Заявки`.
8. Проверьте `Последняя загрузка`, чтобы понимать, когда в последний раз загружали Excel.

## Загрузка Excel

Загрузка Excel выполняется через Telegram-админку бота.

1. Откройте бота в Telegram.
2. Перейдите в `Админ-панель`.
3. Выберите `Импорт Excel`.
4. Отправьте `.xlsx` файл с нужным листом.
5. После обработки откройте web-админку и проверьте `Мониторинг` или `Сигналы`.

После загрузки бот:

- обновляет матчи по постоянному ID матча;
- пересчитывает правила;
- создает или обновляет очередь сигналов;
- сохраняет Decision Log и трассировку решения.

## Работа с сигналами

Раздел `Сигналы` нужен для контроля очереди и ручных операций.

Что смотреть:

- статус сигнала: запланирован, готов, отправлен, отменен;
- группа: VIP или ALL;
- уровень сигнала;
- время отправки;
- результат: выиграл, проиграл, возврат или неизвестно;
- количество успешных и ошибочных доставок.

Основные действия:

1. Откройте нужный сигнал.
2. Проверьте текст сигнала, доставки и трассировку решения.
3. При необходимости вручную выставьте результат сигнала.
4. Если были ошибки доставки, перейдите в `Доставки` и повторите failed/missing.

## Работа с доставками

Раздел `Доставки` показывает отправку сигналов пользователям.

Типовой сценарий:

1. Откройте `Доставки`.
2. Выберите фильтр `Ошибка`, если нужно найти проблемы.
3. Откройте связанную карточку сигнала.
4. Нажмите `Повторить` для failed/missing доставки, если ошибка временная.
5. Не повторяйте успешные доставки вручную: система защищает от дублей, но лучше не создавать лишние действия.

CSV-экспорт доставок можно использовать для отчета или разбора ошибок.

## Заявки на подписку

Пользователь выбирает тариф в боте и создает заявку. После этого он получает реквизиты и контакт специалиста.

Ручная обработка оплаты:

1. Откройте `Заявки`.
2. Выберите тип `Подписки` и статус `Новые`.
3. Откройте заявку.
4. Проверьте пользователя, тариф и сумму.
5. После подтверждения оплаты переведите заявку в `Оплачена` или `Выполнена`.
6. При переводе подписочной заявки в `Оплачена` или `Выполнена` доступ пользователя активируется автоматически по выбранному тарифу.

Если оплата не поступила или заявка ошибочная, переведите ее в `Отменена`.

## Заявки на анализ матча

Анализ матча выполняет специалист вручную.

Сценарий:

1. Откройте `Заявки`.
2. Выберите тип `Анализы`.
3. Откройте заявку.
4. Проверьте текст матча, пользователя и контакт.
5. Переведите заявку в `В работе`, когда специалист взял ее.
6. Переведите заявку в `Выполнена`, когда анализ отправлен пользователю.

Оплата анализа также остается ручной.

## Управление доступом пользователя

Раздел `Пользователи` и карточка пользователя нужны для ручного управления доступом.

В карточке пользователя можно:

- выдать пробный доступ;
- отключить доступ;
- выдать любой платный тариф вручную;
- посмотреть последние доставки;
- посмотреть заявки пользователя.

Используйте ручную выдачу тарифа, если:

- оплату подтвердили вне заявки;
- нужно быстро исправить ошибку;
- пользователь оплатил, но заявка была создана некорректно.

После ручной выдачи проверьте карточку пользователя: тип доступа, статус, остаток сигналов и срок действия.

## Подписки

Раздел `Подписки` показывает пользователей с доступами.

Полезные фильтры:

- `Платные` + `Активные` — текущие платные подписчики;
- `Пробные` + `Активные` — пользователи на trial;
- `Отключенные` — пользователи без активного доступа.

CSV-экспорт подписок можно использовать для сверки и отчетности.

## Настройки

Раздел `Настройки` управляет текстами, которые получают пользователи после создания заявок.

Можно менять:

- реквизиты оплаты анализа;
- контакт специалиста по анализу;
- реквизиты оплаты подписки;
- контакт по подпискам.

После изменения создайте тестовую заявку или проверьте следующую реальную заявку, чтобы убедиться, что пользователь видит актуальные данные.

## Статистика качества

Раздел `Статистика` показывает качество отправленных сигналов.

Что важно:

- сколько сигналов отправлено;
- сколько уже оценено;
- сколько без результата;
- процент захода;
- статистика по группам и уровням.

Кнопка обновления результатов по счету пытается автоматически проставить исходы там, где счет уже известен. Ручные результаты не должны перетираться автоматикой.

## Журнал действий

Раздел `Журнал` показывает действия web-админов.

Логируются:

- изменение статуса заявки;
- изменение доступа пользователя;
- изменение результата сигнала;
- изменение настроек оплаты и контактов.

Используйте журнал, если нужно понять:

- кто выдал доступ;
- кто изменил заявку;
- кто поменял реквизиты;
- кто вручную исправил результат сигнала.

CSV-экспорт журнала доступен кнопкой `CSV`.

## Обслуживание

Раздел `Обслуживание` показывает:

- путь к SQLite базе;
- размер базы;
- размер папки данных;
- размер папки загрузок;
- статус backup;
- дату и размер последнего backup;
- список последних backup-копий;
- кнопку ручного создания backup;
- кнопку проверки последнего backup.

Ручной backup создавайте перед рискованными работами: обновлением сервера, массовой загрузкой, ручными правками базы. После создания нажмите `Проверить последний backup`: исправная копия должна открываться и проходить `integrity_check`.

Если быстро растет папка загрузок или база, сообщите техническому администратору.

### Восстановление из backup

Восстановление выполняет технический администратор на VPS. Общий порядок:

1. Остановить контейнеры `docker compose down`.
2. Сохранить текущую базу отдельным файлом, например `data/algobet.db.before-restore`.
3. Скопировать выбранный backup из `data/backups/` на место `data/algobet.db`.
4. Запустить контейнеры `docker compose up -d`.
5. Проверить `Мониторинг`, `Пользователи`, `Заявки` и `Доставки`.

Перед восстановлением обязательно убедитесь, что выбранная копия проходит проверку в разделе `Обслуживание`.

## Что делать при проблемах

### Не пришел сигнал пользователю

1. Откройте `Доставки`.
2. Найдите пользователя по Telegram ID или посмотрите failed-доставки.
3. Проверьте ошибку.
4. Если ошибка временная, нажмите `Повторить`.
5. Если у пользователя нет доступа, откройте карточку пользователя и проверьте подписку.

### В заявке неправильный тариф

1. Не активируйте такую заявку.
2. Переведите ее в `Отменена`.
3. Попросите пользователя создать новую заявку или вручную выдайте правильный тариф в карточке пользователя.
4. Проверьте действие в `Журнал`.

### Реквизиты изменились

1. Откройте `Настройки`.
2. Обновите реквизиты нужного раздела.
3. Сохраните.
4. Проверьте `Журнал`.

### Неправильный результат сигнала

1. Откройте сигнал.
2. Выставьте правильный результат вручную.
3. Проверьте, что статистика качества обновилась.
4. При споре проверьте запись в `Журнал`.

## CSV-экспорты

CSV доступен в разделах:

- `Сигналы`;
- `Доставки`;
- `Подписки`;
- `Заявки`;
- `Журнал`.

Экспорт учитывает выбранные фильтры там, где они есть.
