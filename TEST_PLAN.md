# План тестирования

## Алгоритм

1. Импорт файла с листом `Турниры`.
2. Проверка минимального CP.
3. Проверка П1 и П2 по отдельности.
4. Проверка выбора большей вероятности при двух прошедших сторонах.
5. Проверка отказа при равных вероятностях CV/CW.
6. Проверка уровней TOP, STRONG, STANDARD.
7. Проверка вывода DS/DV/DY, включая плюс, минус, ноль и пустую ячейку.
8. Проверка сохранения Decision Trace в payload.
9. Проверка записи Decision Log.

## Импорт и сигналы

1. Создание и обновление матчей по `external_match_id`.
2. Отмена сигналов для пропавших матчей.
3. Формирование `ScheduledSignal` для подходящих матчей.
4. Проверка текста сигнала по `templates/signal.txt`.
5. Ручной пересчёт сигнала из админки.

## Доступы и доставки

1. Активация trial-доступа на 9 сигналов.
2. Выдача paid-доступа администратором.
3. Отключение доступа администратором.
4. Отправка только пользователям с доступом.
5. Списание trial-лимита после успешной доставки.
6. Защита от перерасхода trial-лимита при нескольких due-сигналах.
7. Запись `SignalDelivery` со статусом sent/failed.
8. Retry failed/missing без дублей уже sent-доставок.
9. Отображение времени доставок в локальном часовом поясе.

## Интеграционный сценарий

1. Реальный Excel `tests/sample.xlsx` парсится без предупреждений.
2. Создаются Match, SignalDecisionLog и ScheduledSignal.
3. Trial-пользователь получает первые 9 сигналов.
4. Лишние сигналы остаются в ready.
5. Все доставки видны в админке.
